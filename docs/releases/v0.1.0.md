# v0.1.0 — Project Foundation

## Release Summary

v0.1.0 is the Project Foundation release for SOC Investigation Lab. It establishes the
repository structure, engineering workflow, quality controls, documentation, and safe-data
expectations required for incremental development.

The release was published on 2026-09-10 after the Project Foundation scope, documentation,
quality gates, and safe-data requirements were validated successfully.

## What Is Included

- Repository structure for the planned backend, frontend, detection rules, datasets,
  investigation cases, documentation, scripts, and tests.
- A Python 3.12 development environment with reproducible uv dependency management.
- Local and pull-request quality validation.
- Foundation documentation covering product scope, planned architecture, contribution,
  testing, development, security, and local configuration.
- Safe-data handling requirements for a public defensive-security repository.
- A portfolio-ready README that distinguishes implemented foundations from planned SOC
  capabilities.

## Engineering Foundation

- Python 3.12 project metadata and version constraints.
- uv dependency groups and a committed lockfile for reproducible environments.
- Ruff linting and formatting checks.
- Strict mypy static type checking.
- pre-commit hooks for the configured Python quality checks.
- A pytest layout with a passing foundation smoke test.
- A pull-request GitHub Actions workflow exposing the required `Backend quality` check.
- Editor and local environment-file conventions without application-specific runtime
  configuration.

## Documentation Foundation

- Project purpose, target users, goals, boundaries, and explicit non-goals.
- Planned modular-monolith architecture, component responsibilities, and logical data flow.
- Issue, branch, commit, Pull Request, review, Testing, and squash-merge conventions.
- Development tooling, testing, and local configuration guidance.
- A professional project landing page with an explicit roadmap and honest implementation
  status.

## Security and Safe Data Policy

The foundation prohibits secrets, credentials, personal data, confidential enterprise
information, employer or client telemetry, production logs, and executable malware. Future
telemetry and investigation artifacts must use synthetic data, controlled-lab data, or public
data that is clearly safe and permitted for reuse.

## Current Limitations

v0.1.0 establishes the engineering and documentation foundation only. It does not yet provide:

- Windows Event Log processing.
- Sysmon processing.
- An event-normalization pipeline.
- Executable detection rules.
- A detection engine.
- Alert generation.
- An alert lifecycle.
- Analyst triage.
- An investigation workflow.
- IOC enrichment.
- MITRE ATT&CK runtime enrichment.
- Timeline generation.
- False Positive or True Positive verdict execution.
- A severity or priority workflow.
- An escalation workflow.
- A backend API.
- A persistence layer.
- An analyst web interface.

These capabilities belong to later roadmap milestones and are not implemented in v0.1.0.

## Validation

Before publication, the Project Foundation release was validated through:

- Completion of Issues #1 through #12.
- Foundation documentation consistency review.
- Dependency lock validation.
- Ruff linting.
- Ruff formatting checks.
- Strict mypy checks.
- pytest.
- All configured pre-commit hooks.
- Repository-wide sensitive-data review.
- Pull-request GitHub Actions validation through the required `Backend quality` check.

This release was published after the foundation, quality, documentation, and safe-data
validation checks above completed successfully.
