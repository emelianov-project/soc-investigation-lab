# v0.3.0 — Detection Engine

## Overview and output boundary

v0.3.0 adds deterministic, explainable, single-event detection to the v0.2.0
event-processing layer. Its output is `DetectionMatch`, not an Alert or a
maliciousness verdict.

The existing ingestion path remains:

`Windows Event XML → RawWindowsEvent → Parser Registry → Source Normalizer → NormalizedEvent`

The detection layer consumes an already validated `NormalizedEvent` and validated
declarative rules:

`NormalizedEvent + DetectionRule collection → Detection Engine → DetectionMatch collection`

Windows Security Events 4624, 4625, and 4688 and Sysmon Events 1, 3, 11, and 22
remain the seven supported XML event identities. Detection operates on their typed
normalized contexts, not raw XML, binary `.evtx`, or live telemetry.

## Declarative rule format

`DetectionRule` defines a stable lowercase-slug `id`, positive integer `version`,
non-empty `title` and `description`, non-empty unique `categories`, optional
non-empty unique `sources`, and one `condition` tree. Supported categories are
`authentication`, `process`, `network`, `file`, and `dns`; sources are
`windows_security` and `sysmon`. A rule using `source_data` must declare its sources.
Unknown fields and unsupported operators are rejected.

Conditions are leaves (`field`, `op`, and an operator-appropriate `value`) or
recursive `all`, `any`, and `not` nodes. `all` and `any` contain ordered non-empty
child lists; `not` has one child. Existence operators omit `value`. Rule trees are
bounded to depth 8 and 64 leaves. Rules are data, not Python expressions or plugins.

## Safe loading and semantic validation

`load_detection_rules(rule_root)` accepts an explicit absolute directory and
loads regular `.yaml`/`.yml` files recursively in root-relative POSIX path order.
The controlled library is `rules/windows/`. The resolved root is the trust
boundary: escapes, links below the root, and Windows reparse points are rejected.
Keep the library stable while loading; these checks are not an operating-system
sandbox for a concurrently hostile filesystem.

Files are read as UTF-8. Safe YAML parsing rejects malformed or multi-document
input, empty/non-mapping documents, explicit tags (including Python/object tags),
anchors, aliases, merge keys, and duplicate mapping keys. There is no dynamic
execution, remote rule fetching, or plugin discovery.

The acceptance sequence is:

1. Safe YAML parsing into one mapping per file.
2. Pydantic structural validation through `DetectionRule`.
3. Shared semantic validation of every leaf for every declared target category.
4. Duplicate-ID checks across the library, including rules with different versions.

Semantic validation rejects unsupported context fields, incompatible operators or
operand types, invalid IP/CIDR literals, and invalid or naive timestamp literals
before any event is evaluated. `source_data` remains source-scoped text. Runtime
semantic checks remain defense in depth for directly constructed or changed
objects; they are not a substitute for load-time validation.

An empty valid library returns an empty tuple. Any file, decoding, YAML, model,
semantic, or duplicate-ID failure aborts the whole load, never returning a partial
rule set. Controlled loader errors provide relative-path/category context without
dumping rule contents.

## Field resolution and operators

Common fields are `source`, `provider`, `event_id`, `channel`, `timestamp`,
`computer`, `record_id`, and `category`. `context.<field>` accesses only declared
fields of the actual category's typed context; `source_data.<name>` accesses one
retained string. Arbitrary traversal, indexing, wildcards, and method calls are
not supported. Invalid paths are errors, not missing data.

The complete operator set is:

| Operators | Semantics |
| --- | --- |
| `equals`, `not_equals` | Strict typed scalar equality/inequality |
| `contains`, `contains_any` | String substring match / at least one listed substring |
| `starts_with`, `ends_with` | String prefix/suffix match |
| `in`, `not_in` | Strict scalar membership/non-membership in a non-empty list |
| `exists`, `not_exists` | Presence/absence without an expected operand |
| `greater_than`, `greater_or_equal`, `less_than`, `less_or_equal` | Normalized integer ordering only |
| `ip_in_cidr` | Typed IPv4/IPv6 address membership in a CIDR network |

Strings are case-sensitive with no path, hostname, or Unicode normalization.
Enums use their declared string values. Integers are not coerced from strings or
booleans; numeric-looking `source_data` stays text. IP equality/membership and
CIDR checks use typed addresses/networks; address-family mismatch returns false.
Timezone-aware ISO-8601 timestamp literals compare as UTC instants for equality
and membership, not lexicographically. Timestamp ordering and regex are not
supported. Invalid operator/type pairings raise controlled evaluation errors.

## Three-valued evaluation and explanations

Field resolution distinguishes `present`, `missing` (a retained source-data key),
and `absent` (a declared optional field whose value is `None`). For valid
comparisons, missing/absent data yields `unknown`, including `not_equals` and
`not_in`; `exists` is false and `not_exists` is true.

`all` is false if any child is false, true if all are true, and otherwise unknown.
`any` is true if any child is true, false if all are false, and otherwise unknown.
`not` reverses true/false and preserves unknown. Every child is evaluated in
declared order without short-circuiting.

`ConditionTrace` records the complete tree with stable locations such as `$`,
`$.all[0]`, and `$.not`. Leaf evidence includes field, operator, expected value
where applicable, actual value or missing/absent marker, and outcome. Logical
nodes retain ordered child traces and their aggregate outcome.

`evaluate_event(event, rules)` validates collection identities, evaluates
applicable rules in ascending rule-ID order, and returns a tuple containing only
true-root matches. Category and optional source targeting precede evaluation.
False/unknown roots produce no match; an evaluation failure does not return
earlier partial matches. There is no cross-event state.

Each `DetectionMatch` contains rule ID, version, title, the supplied normalized
event, a true root outcome, and the complete trace. These in-memory objects are
not frozen snapshots or automatically redacted exports: callers must preserve
input evidence and apply the security policy before sharing actual values.

## Initial rule library

All six rules are version 1, use normalized context fields, and have synthetic
positive, negative, and optional-data coverage.

| Rule ID | Category | Single-event signal |
| --- | --- | --- |
| `powershell-encoded-command` | process | PowerShell-family image suffix and an explicit encoded-command argument marker |
| `certutil-suspicious-arguments` | process | `certutil.exe` image suffix with a transfer/decode argument marker |
| `failed-remote-authentication` | authentication | Failed network or remote-interactive logon (type 3 or 10) |
| `powershell-network-connection` | network | PowerShell-family process image associated with a connection |
| `dns-suspicious-query-marker` | dns | Literal synthetic `tunnel-test` query marker |
| `startup-folder-file-activity` | file | Literal Windows Startup-folder path fragment |

These are educational signals, not enterprise coverage claims. Exact markers can
miss variants and legitimate activity can match. They do not decode commands,
count authentication failures, prove persistence, classify network destinations,
or implement general DNS-tunneling detection.

## Testing and validation

Coverage spans model contracts, safe loading, the load-time operator/type matrix,
field resolution, typed comparisons, complete three-valued traces, engine
targeting/order, the real six-rule library, and XML-to-match integration/failure
paths. Integration uses the public normalization, loading, and engine functions;
it covers ordinary non-matches, optional-data absence, repeatability, malformed
rules, duplicate IDs, and semantic loading failures.

The release-preparation quality gate is:

```console
uv lock --check
uv sync --locked --group dev --group test
git diff --check
uv run --no-sync ruff check .
uv run --no-sync ruff format --check .
uv run --no-sync mypy backend/tests
uv run --no-sync mypy tests/integration
uv run --no-sync pytest
uv run --no-sync pre-commit run --all-files
```

Required Pull Request CI is the `Backend quality` job in `Backend CI`.

Local release-preparation validation on Windows with Python 3.12 passed the
commands above. Full pytest collected 1,143 tests: **1,141 passed, 2 skipped**.
The two existing direct-symlink tests were skipped because the OS did not permit
symlink creation; deterministic link/path-containment tests still ran and passed.
This local result is distinct from the required Pull Request CI gate.

## Safe data and current limitations

Fixtures, rule examples, and test telemetry are synthetic and public-safe,
including documentation-reserved addresses and example domains. YAML is data
only. No credentials, production telemetry, executable malware, or real
employer/customer data belong in the repository. See the
[security policy](../../SECURITY.md) for safe-data and export requirements.

The release-preparation tracked-content review covered repository configuration,
code, tests, documentation, all six rules, and the Windows XML fixtures. It found
no sensitive/private content; fixture provenance and example values were also
reviewed against the security policy.

v0.3.0 does not implement Alert generation or lifecycle management, analyst
triage, stateful/time-window correlation, persistence or database storage, IOC
enrichment, investigation workflow, verdicts, escalation, severity/priority,
backend API, analyst web UI, live collection, or streaming/Kafka infrastructure.
It is not Sigma-compatible and does not execute regex, arbitrary expressions,
or plugins. Detection remains one normalized event at a time and ends at
`DetectionMatch`.
